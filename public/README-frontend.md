# 프런트엔드 안내

## 파일 구성

- `index.html`: 입력 폼, 타임라인·지도·로그 영역과 JSON 모달의 뼈대입니다.
- `css/style.css`: 반응형 2열 레이아웃과 순례 분위기의 색상, 타임라인/마커 스타일입니다.
- `js/api.js`: REST 요청과 이름 있는 SSE 이벤트 연결을 담당합니다.
- `js/app.js`: 폼, 상태, 스트림, 수정 요청, 새로고침 복원과 목업 모드를 연결합니다.
- `js/timeline.js`: 날짜 탭과 장소별 수직 타임라인을 렌더링합니다.
- `js/map.js`: Naver Maps SDK를 동적으로 로드하고 마커/경로를 그립니다.
- `js/log.js`: 진행 배지와 의사결정 로그를 표시합니다.
- `dev/mock-plan.json`: 백엔드 없이 볼 수 있는 2일 대전·당진 예시 일정입니다.

## 이벤트와 화면의 연결

`status` 이벤트는 상단 진행 배지와 단계 표시(후보 수집 → 조사 → 일정 작성 → 이동 계산)를 갱신합니다. `log` 이벤트는 종류별 색상 태그를 붙여 하단 로그에 누적하고 자동으로 아래로 이동합니다. `result` 이벤트는 타임라인, 선택 일자의 지도, 비용 막대 및 수정 영역을 갱신합니다. `error` 이벤트는 빨간 진행 배지로 오류를 알립니다.

## 목업 데모

정적 파일을 제공하는 서버에서 `public/index.html?mock=1`을 열면 됩니다. 목업에서는 300ms 간격으로 상태/로그 이벤트를 재생한 뒤 `dev/mock-plan.json`을 표시합니다. 실제 지도 SDK는 호출하지 않으며, SSE 및 API도 호출하지 않습니다.

## 알려진 제한

- Naver 지도는 발급받은 Client ID와 해당 Web 서비스 URL 등록이 있어야 표시됩니다.
- PDF 링크는 백엔드의 `/api/plans/{id}/pdf` 구현 전에는 404일 수 있습니다.
- 일정 데이터는 백엔드 메모리 저장소의 보존 기간에 따라 새로고침 후 복원되지 않을 수 있습니다.
